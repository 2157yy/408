一、为什么队列要"循环"？—— 假溢出问题

用数组 A[0..n−1] 顺序存储队列时，出队只移动 front、入队只移动 rear。出队几次后 front 前面的单元就再也用不到了： 明明 A[0..k] 还是空的，rear 却已经到了数组末尾报"队满"——这叫假溢出。

解决办法是把数组首尾逻辑相连成一个环：下标前进时统一做取模运算，i → (i+1) mod n， rear 走到末尾就绕回 0 号单元，腾出的空间被重复利用。入队、出队都只需移动指针和存取一个元素，时间复杂度均为 O(1)。

二、两种指针约定 —— 审题的第一关键

循环队列的一切公式都取决于一个问题：rear 到底指向谁？做题前必须先看清题目约定。

常见约定（严蔚敏 / 王道默认）本题约定（2011 年 408 真题）
front指向队头元素指向队头元素
rear指向队尾元素的下一位置（插入点）指向队尾元素本身
初始化front = rear = 0front = 0，rear = n−1
入队先存入 A[rear]，再 rear=(rear+1) mod n
（先存后移）		先 rear=(rear+1) mod n，再存入 A[rear]
（先移后存）
出队先取 A[front]，再 front=(front+1) mod n先取 A[front]，再 front=(front+1) mod n
谁会动入队只动 rear，出队只动 front

记忆方法：rear 指向的位置必须"能用"。常见约定里 rear 指向空位，所以可以直接存进去再后移； 本题约定里 rear 指向队尾元素本身，若直接存会覆盖队尾，所以必须先移动到下一个空位再存。

入队 / 出队代码（常见约定）

// 入队：先判满，满则上溢报错
Q[rear] = x;
rear = (rear + 1) % n;

// 出队：先判空，空则下溢报错
x = Q[front];
front = (front + 1) % n;

入队代码（本题约定，注意顺序相反）

// 入队：先判满
rear = (rear + 1) % n;   // 先移动
Q[rear] = x;             // 再存入

三、队空 / 队满 / 元素个数怎么算

采用常见约定（front 指队头、rear 指队尾下一位置）时，front == rear 既可能表示"空"也可能表示"满"， 无法区分，于是有三种解决方案：

方案队空条件队满条件元素个数最多存放
① 牺牲一个单元front == rear(rear+1) % n == front(rear−front+n) % nn−1 个
② 增设 size 变量size == 0size == nsizen 个
③ 增设 tag 标志front==rear 且 tag==0front==rear 且 tag==1(rear−front+n) % nn 个
  • 方案①：rear 永远不追上 front，留 1 个空单元作"哨兵"，代价是少存 1 个元素。这是教材默认方案。
  • 方案②：size 随入队 +1、出队 −1，最直观，能存满 n 个。
  • 方案③：tag 记录最后一次操作——入队后置 tag=1，出队后置 tag=0。当 front==rear 时： 若最后一次是入队导致指针重合 → 队满；若是出队导致 → 队空。
  • 长度公式 (rear−front+n) % n 里的 +n 是为了防止 rear 在 front 之后（下标更小）时出现负数。

本题约定下的对应公式

  • 队空：front == (rear+1) % n（初始 front=0，rear=n−1，恰好 0 == n % n = 0 成立）
  • 非空时元素个数：(rear−front+n) % n + 1（注意比常见约定多加 1，因为首尾都指向真实元素）
  • 队满（存满 n 个）时 rear 的下一个位置恰好是 front：(rear+1) % n == front—— 与队空条件完全相同！所以这种约定下指针法无法区分空和满，必须借助 size / tag / 牺牲单元。 若牺牲一个单元（最多 n−1 个），队满条件变为 (rear+2) % n == front。

四、例题详解（2011 年 408 真题第 2 题）

题目：已知循环队列存储在一维数组 A[0..n−1] 中，且队列非空时 front 和 rear 分别指向队头元素和队尾元素。 若初始时队列为空，且要求第 1 个进入队列的元素存储在 A[0] 处，则初始时 front 和 rear 的值分别是：
A. 0, 0　　B. 0, n−1　　C. n−1, 0　　D. n−1, n−1
  1. 审题找钥匙：rear 指向队尾元素本身（不是下一空位）→ 入队必须先移动 rear 再存入；front 指向队头元素 → 入队时 front 不动，出队时才后移。
  2. 求 rear 初值：第 1 个元素要落在 A[0]，即首次入队执行 (rear初+1) mod n = 0 → rear初 = n−1。
  3. 求 front 初值：入队不改变 front；第 1 个元素入队后既是队头又是队尾，front 必须指向 A[0] → front初 = 0。
  4. 自洽验证：初始 (0, n−1)，队空条件 front == (rear+1) mod n → 0 == 0 ✓；首次入队后 front=rear=0，同时指向 A[0] ✓。
  5. 排除错误选项： A (0,0) 与 C (n−1,0) 的 rear=0，首次入队元素落在 A[1] ✗； D (n−1,n−1) 的 rear 对，元素确实落在 A[0]，但 front 停在 A[n−1] 这个空单元上，没有指向队头 ✗。
✔ 正确答案：B（front = 0，rear = n−1）

常见误选 D 的原因：习惯性套用"空队列 front==rear"的常见约定。但本题 rear 指向队尾元素本身， 判空条件已变成 front == (rear+1) % n，初始不需要也不应该让两指针相等。做题时先确认"rear 指向谁"，再动笔。

五、易错点清单

  • 判空、判满公式不能死记硬背，先确认 rear 指向"下一空位"还是"队尾元素本身"。
  • 长度公式 (rear−front+n) % n 中的 +n 是防负数，别忘了 mod。
  • 牺牲单元方案最多存 n−1 个元素，选择题里常挖这个坑。
  • tag 方案中 tag 表示"最近一次操作是入队还是出队"，不是"队列是否为空"。
  • 指针初始值类题目：抓住"入队只动 rear、出队只动 front"，从第 1 个元素落在哪倒推初始值。
  • 循环队列判满后仍可能发生上溢（真满时再入队），这是"顺序存储"的固有缺点，与链式队列对比是常考点。
